# PhotoOK (photook)

원하는 폴더 구조로 사진·동영상을 자동 분류하는 Windows 프로그램입니다.

SD 카드나 휴대폰에서 PC로 옮겨 둔 폴더, 여기저기 흩어진 폴더의 사진을 촬영일·기기·파일 형식에 맞춰 내 사진 보관 폴더(아카이브)로 옮겨 줍니다. 어떤 폴더 구조로 정리할지는 사용자가 직접 정하고, 실행하기 전에 결과를 미리 보고, 실행한 뒤에도 되돌릴 수 있게 만드는 것이 목표입니다.

## 무엇을 하나요

- **가져오기**: SD 카드·휴대폰에서 PC로 옮겨 둔 폴더·그 밖의 폴더의 사진을 아카이브로 복사합니다.
- **흩어진 폴더 흡수 (예정)**: 다운로드 폴더나 예전 폴더에 있는 사진을 같은 규칙으로 아카이브에 합칩니다.
- **아카이브 재정리 (예정)**: 이미 아카이브에 있지만 규칙과 어긋난 파일을 제자리로 옮깁니다.
- **촬영 단위 묶기**: 하루를 한 촬영으로 묶습니다. 자정 넘어 찍은 사진을 전날로 칠지 정할 수 있습니다.
- **폴더 구조 직접 설계**: `{연도}\{날짜}\{기기}\{포맷}`처럼 폴더 단계를 템플릿으로 정합니다. 기기 이름에 별명을 붙일 수 있고, 촬영일이나 기기를 알 수 없는 파일은 `판단 필요` 폴더로 따로 모아 사용자가 판단하게 합니다.
- **딸린 파일 함께 옮기기**: RAW 파일 옆의 편집 정보 파일(`.xmp` 등), 라이브 포토의 동영상처럼 같은 이름으로 묶인 파일은 항상 함께 움직입니다.

정리 결과는 예를 들어 이렇게 됩니다.

```
아카이브\
├─ 2026\
│  ├─ 2026-10-14\
│  │  ├─ X100VI\
│  │  │  ├─ JPG\
│  │  │  └─ RAW\
│  │  └─ Z f\
│  │     └─ JPG\
│  └─ 2026-10-15\ …
└─ 판단 필요\
   └─ 촬영일 없음\ …
```

## 실행 방법

Windows 전용입니다(.NET 10, WPF). [.NET 10 SDK](https://dotnet.microsoft.com/download)를 설치한 뒤 저장소 폴더에서 실행합니다.

```powershell
dotnet run --project src/PhotoOk
```

### 사용 방법

1. **가져올 곳 고르기**: 연결된 SD 카드(이동식 드라이브)나 폴더를 고르고, 사진을 넣을 보관 폴더와 정리 방식(프리셋)을 정합니다. 가져오는 방식은 기본값인 '복사 (원본을 그대로 둠)'을 권합니다. '이동'을 고르면 같은 드라이브에서는 원본이 옮겨지고, 다른 드라이브에서는 이동을 골라도 복사됩니다.
2. **정리 미리보기**: 폴더 트리에서 정리 후 모양을 보고, 파일을 고르면 '왜 이 경로인가'에서 이유를 확인합니다. 사진·동영상 정보가 없으면 파일 이름에서 날짜를 읽고, 그래도 알 수 없는 파일은 `판단 필요` 폴더로 갑니다. 사진·동영상이 아닌 파일(문서 등)은 가져오지 않으며, 미리보기의 '가져오지 않는 파일'에서 목록을 볼 수 있습니다. 연결 폴더(정션·심볼릭 링크·일부 클라우드 폴더)는 들어가지 않고 오류 목록에 알립니다.
3. **이벤트 이름 적기**: 촬영을 하나 골라 이벤트 이름을 적으면 폴더 이름에 붙습니다. 비워 두면 날짜만 쓰입니다.
4. **실행**: 미리보기가 마음에 들면 실행합니다. 복사로 가져올 때 원본은 지우지 않습니다.
5. **작업 기록에서 되돌리기**: 실행한 작업은 작업 기록에 남습니다. 결과가 마음에 들지 않으면 기록에서 해당 작업을 골라 되돌릴 수 있고, 되돌려도 파일을 지우지 않고 보관 폴더로 옮깁니다.

내 정리 방식은 `%AppData%\PhotoOk\presets\` 폴더에 프리셋 파일(`*.json`)로 넣어 두면 프리셋 목록에 나타납니다.

## 파일 보존 원칙

PhotoOK는 사진을 잃지 않는 것을 가장 먼저 생각합니다.

1. **원본을 고치지 않습니다.** 원본 파일은 읽기 전용으로만 열고, 사진 파일 안의 정보(EXIF 등)를 고쳐 쓰지 않습니다.
2. **원본을 지우지 않습니다.** 다른 드라이브(SD 카드, 외장 디스크)에서 가져올 때는 항상 복사만 합니다. 같은 드라이브에서 '이동'을 고르면 원본을 지우지 않고 아카이브의 새 자리로 옮깁니다. 복사와 검증이 끝나면 원본 정리는 직접 하시면 됩니다.
3. **영구 삭제를 하지 않습니다.** 프로그램이 파일을 치워야 할 때(되돌리기 때의 복사본, 검증에 실패한 임시 파일)는 아카이브의 `.photook\되돌림\<실행ID>\` 폴더로 옮겨 둡니다. 같은 드라이브 안에서 옮기는 것이라 내용이 사라지지 않고, 휴지통도 쓰지 않습니다. 실제로 지우는 것은 비어 있는 폴더뿐입니다.
4. **덮어쓰지 않습니다.** 가져갈 자리에 같은 이름의 파일이 이미 있으면, 내용이 같을 때는 중복으로 보고 건너뛰고, 내용이 다르면 이름에 순번을 붙여 둘 다 남깁니다.
5. **검증한 뒤에만 이름을 붙입니다.** 복사는 먼저 `파일이름.photook-tmp`라는 임시 이름으로 쓰고, 처음부터 다시 읽어 원본과 해시(xxHash64)가 같은지 확인한 다음에야 진짜 이름으로 바꿉니다. 도중에 프로그램이 꺼져도 반쯤 쓴 파일이 진짜 이름으로 남지 않습니다.
6. **재정리는 같은 드라이브 안의 이름 바꾸기로만 합니다.** 두 파일이 서로 자리를 바꿔야 하면 임시 이름을 거쳐 하나도 덮어쓰지 않습니다.
7. **처음 쓰는 정리 방식은 반드시 미리보기를 거칩니다.** 결과를 보지 않고 바로 실행하는 경로는 없습니다.

### 기록과 되돌리기

- 실행할 때마다 모든 작업을 시작하기 전에 계획을 기록하고, 작업 하나하나의 시작과 끝을 기록합니다. 기록은 `%LocalAppData%\PhotoOk\journal\`과 아카이브의 `.photook\journal\` 두 곳에 남깁니다.
- 실행 중에 컴퓨터가 꺼지거나 드라이브가 빠져도 기록으로 **이어 하기**를 할 수 있습니다. 끊긴 작업은 디스크 상태를 확인한 뒤 마무리합니다.
- **되돌리기**는 기록을 거꾸로 따라가며 복사본을 되돌림 폴더로 옮기고, 옮긴 파일을 원래 자리로 돌려놓고, 이번 실행이 만든 빈 폴더를 치웁니다.
  - 복사본은 원본이 아직 있고 내용이 같을 때만 치웁니다. 원본을 이미 정리했다면 복사본이 유일한 사본이므로 그대로 둡니다.
  - 되돌리기는 어떤 파일도 덮어쓰지 않습니다. 옮긴 파일의 원래 자리에 다른 파일이 생겼다면, 자리 바꾸기 때문에 프로그램이 임시 이름으로 옮겨 두었던 파일은 숨겨지지 않도록 원래 이름 옆에 `이름_1.확장자`처럼 순번을 붙여 돌려놓고 알려 드립니다. 그 밖의 파일은 지금 있는 자리에 그대로 두고 알려 드립니다.
  - 실행 뒤에 바뀐 파일은 그대로 두고 알려 드립니다. 단, 임시 이름에 남아 있던 파일은 숨겨지지 않도록 항상 보이는 이름으로 꺼냅니다.
  - 되돌리기도 기록하므로 중간에 끊겨도 다시 실행하면 이어서 처리합니다.
- 이 원칙은 테스트로 확인합니다. 파일을 바꾸는 모든 단계에서 프로그램이 강제로 꺼진 상황을 하나씩 만들어, 원본이 그대로이고 이어 하기·되돌리기 뒤에도 파일이 보존되는지 검사합니다.
